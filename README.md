# Phosphor

## Стенд

Безголовый замер ключевых операций ядра на синтетическом дампе. Цели — раздел 5.1 спеки.

```bash
python3 tools/gen_vcd.py --out big.vcd                 # 10000 сигналов, ~600 МиБ, детерминированно
.venv/bin/conan install . --build=missing -s compiler.cppstd=23 -s build_type=Release
cmake --preset conan-release -DPHOSPHOR_BUILD_BENCH=ON
cmake --build --preset conan-release
build/Release/bin/phosphor-bench big.vcd --cache bench-cache
```

Параметры генератора: `--signals`, `--size-mib`, `--seed`. Стенд принимает `--cache`, `--rows`
(по умолчанию 50: 40 однобитных и шин плюс 10 `real`) и `--width` (1920). Store дампа в каталоге
кэша перед замером удаляется, поэтому первая индексация всегда настоящая.

### Исходная точка (до сводок этапа 2)

Машина: Intel Core i7-12700K, NVMe, Release, файловый кэш ОС тёплый (дамп только что
сгенерирован и прочитан). Дамп 600 МиБ, 10000 сигналов, ось 0 .. 55.824 мкс.

| Операция | мс | Порог, мс | Итог |
| --- | ---: | ---: | --- |
| Первая индексация | 7906 | - | - |
| Повторное открытие | 4.8 | 1000 | OK |
| Кадр, 1/10000 | 1.0 | 100 | OK |
| Кадр, 1/100 | 1.4 | 100 | OK |
| Кадр, весь диапазон | 408.0 | 100 | FAIL |
| Непрерывные запросы, окно 1/100 (лёгкая нагрузка) | 118 запросов, 118 кадров; первый через 2.4-3.2 мс, медиана промежутка 16.0 мс, максимальный разрыв 20.0-20.6 мс | - | только отчёт |
| Непрерывные запросы, весь диапазон (тяжёлая нагрузка) | 118-119 запросов, 0 кадров за 2 с; максимальный разрыв равен всему замеру (около 1.9 с) | - | только отчёт |

Порядок замера кадров: окна лежат в разных местах диапазона (1/10000 на 70 %, 1/100 на 20 %),
так что каждый кадр — прыжок в новую область, а весь диапазон идёт последним. Повторные
замеры тех же окон (в таблицу не вынесены) дают 0.5 / 1.1 / 400 мс.

Непрерывный замер: новый запрос каждые 16 мс в течение 2 с через настоящий `Renderer`. Разрыв
считается от первого запроса до первой доставки, между доставками и от последней доставки до
остановки; печатаются также время первого кадра, медиана промежутка и время последней доставки.
При окне 1/100 оно сдвигается на 1 % своей ширины за запрос и отражается от границ данных, так
что нагрузка постоянна. При полном диапазоне окно не меняется, а новый кадр вынуждает сдвиг
курсора A на 1 % диапазона за запрос. Результат: кадр на весь диапазон строится дольше периода
запросов, и каждый новый запрос бросает строящийся кадр, поэтому ни один кадр не доставляется
(голодание при непрерывном вводе). Это исходная точка для этапа 2 (сводки и грубая картинка).

Кадр на весь диапазон не укладывается в порог: без сводок min/max прореживание читает
каждое изменение. Это ожидаемо до этапа 2. Холодный файловый кэш не замерялся.
