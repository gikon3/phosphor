# Phosphor v1 — спецификация

Дата: 2026-10-24. Статус: черновик на согласование.

Phosphor — настольный просмотрщик временных диаграмм на Qt6 поверх библиотек
[wasafe](../../../../wasafe) (хранение и ленивый доступ к значениям) и
[wasafe-vcd](../../../../wasafe-vcd) (разбор VCD). Платформы — Linux и Windows.

Пометка **[решение спеки]** означает выбор автора документа, который отдельно с
заказчиком не обсуждался; остальное — согласовано.

---

## 1. Зачем

Источник диаграмм — VCD из Icarus Verilog и подобных симуляторов (позже другие
форматы через `Reader` wasafe). В них есть и цифра, и аналог — `real`-переменные
поведенческих моделей. Существующие открытые просмотрщики (GTKWave, Surfer)
сносно показывают цифру, но аналог в них смотреть неудобно:

- масштаб по Y только автоматический в границах видимого окна — диапазон
  «убегает» при прокрутке, сравнивать участки невозможно;
- высоту дорожки меняют только строками-расширителями;
- нельзя наложить несколько сигналов на одну ось;
- трудно снять значения сразу в нескольких точках.

**Ориентир — симбиоз двух инструментов Cadence:** SimVision для цифры (работа
с сигналами, навигация, поиск, в будущем сравнение баз) и Virtuoso (ViVA) для
аналога (панели, наложения, масштабы, значения на курсорах). Целимся в
удобство этой пары; получится лучше — хорошо. Где поведение не описано в этой
спеке явно, разработчик берёт за образец их, а не GTKWave/Surfer. Phosphor
должен быть просмотрщиком, где цифра и аналог равноправны, и при этом быстрым.

## 2. Цели, не-цели, анти-цели

### Цели v1

1. Открыть один или несколько VCD (до сотен МиБ; ориентир — 600 МиБ) и смотреть
   цифровые и аналоговые сигналы в одном виде.
2. Удобный аналог: ручной фиксируемый масштаб Y, наложение сигналов, значения
   на пересечениях с курсорами, тянущаяся высота, ступенька/интерполяция.
3. Базовая работа с сигналами: форматы, реверс битов, папки-группы, составные
   сигналы (виртуальная шина/структура).
4. Масштаб и прокрутка по времени, два курсора с Δt.
5. Поиск: сигнал в иерархии, значение сигнала по всей диаграмме, фронты.
6. Цикл «поправил RTL → пересимулировал → перечитал»: вид сохраняется.
7. Сохранение вида в файл сессии.

### Не-цели v1

(следующие этапы, у каждого будет своя спека; здесь они только
накладывают ограничения на архитектуру — раздел 8):

- live-просмотр недописанного файла и автообновление по таймеру;
- математика над сигналами;
- сравнение баз (diff в духе SimVision);
- редактирование диаграмм;
- сохранение в другой формат;
- несколько окон над одной БД;
- MCP-сервер для анализа агентом;
- форматы, кроме VCD;
- пользовательские таблицы «значение → имя» для векторов.

### Анти-цели

- **Медленная работа.** Это главный критерий провала: даже при полном наборе
  удобных функций медленный Phosphor не нужен. Цели производительности —
  в разделе 5.1, они измеряемы и проверяются стендом.
- Замороженный GUI в любой ситуации (загрузка, поиск, отрисовка большого окна).
- Автомасштаб, который нельзя выключить.

## 3. Основной сценарий

1. `phosphor tb.vcd` (или «Открыть», или перетаскивание файла в окно).
2. Пока идёт индексация — прогресс с отменой; GUI живой.
3. В дереве иерархии фильтром находит сигналы, добавляет в вид, раскладывает:
   цифру — строками и группами, аналог — в панели.
4. Ставит курсоры, смотрит значения, ищет значения и фронты.
5. Правит RTL, перезапускает симуляцию, нажимает «Перечитать» — набор строк,
   форматы, панели, масштабы, курсоры и видимое окно на месте.
6. Сохраняет сессию, чтобы завтра открыть тот же вид.

## 4. Функциональные требования v1

### 4.1. Источники (дампы)

- Можно открыть **несколько дампов одновременно** в одном виде, без
  дополнительных операций над ними (сравнения нет). Каждый дамп — отдельный
  корень в дереве иерархии с короткой меткой (по умолчанию — имя файла,
  переименовывается). Сигналы разных дампов свободно смешиваются в строках,
  наложениях и составных сигналах.
- **Общая ось времени.** У дампов могут быть разные `$timescale`; всё
  приводится к общей шкале (самой мелкой среди открытых). Отображение времени —
  с автоматическим выбором единиц (fs…s).
- **Кэш индекса.** VCD индексируется в `.wsfstore` через
  `makeIndexingBuilder`; повторное открытие неизменённого дампа идёт через
  `openStore` и почти мгновенно. По умолчанию store всегда строится
  индексирующим builder'ом (одна ветка кода для малых и больших дампов) и лежит
  в пользовательском каталоге кэша (`QStandardPaths::CacheLocation`), а не
  рядом с дампом — чтобы не мусорить в каталоге симуляции. Ключ — абсолютный
  путь + размер + mtime; несовпадение → переиндексация. Политика очистки кэша
  (лимит объёма, LRU) — на усмотрение разработчика.
  В v1 это поведение по умолчанию без настройки, но выбор стратегии
  изолирован в одном месте ядра, потому что позже появятся выбор и настройка:
  режим хранения (в ОЗУ через `makeMemoryBuilder` / store на диске) и место
  store (кэш / рядом с дампом / заданный каталог), глобально в `QSettings` и,
  возможно, для отдельного дампа.
- **Загрузка в фоне** с прогрессом и отменой. GUI во время загрузки не
  блокируется; остальные открытые дампы остаются доступны.
- **Перечитать** — для каждого дампа отдельно. Строки ссылаются на сигналы по
  полному пути, поэтому после переиндексации разрешаются заново. Сигнал,
  исчезнувший из дампа, остаётся в виде пустой строкой с пометкой «нет в
  дампе», а не удаляется молча. Желательно (не обязательно) показывать дерево
  сразу после разбора заголовка (`readHeader`), до окончания индексации значений.
- Ошибка разбора (битый VCD) — понятное сообщение с текстом из
  `WaSafe::Exception`; приложение не падает, прочие дампы не страдают.

### 4.2. Главное окно

Выбран вариант «гибрид» (макет: `.superpowers/brainstorm/*/content/layout.html`,
вариант C):

```plaintext
┌ тулбар: масштаб −/+ · fit · ◀ фронт ▶ · поиск ────────────────────────────┐
├─────────────┬──────────────┬─────────┬─────────────────────────────────────┤
│ Иерархия    │ Имя          │ @A / @B │ линейка времени  [A]──Δt──[B]       │
│ [фильтр]    ├──────────────┼─────────┼─────────────────────────────────────┤
│ ▾ tb.vcd    │ clk          │ 1 / 0   │ ┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐                  │
│   ▾ top     │ ▾ ctrl       │         │                                     │
│     ▸ u_dut │   state      │ RUN/RUN │ <IDLE><INIT><  RUN  ><HOLD>         │
│ ▾ run2.vcd  │   data[7:0]  │ 3C / 12 │ <00><A5><3C><7F><12><FF>            │
│   ...       │ ▾ аналог 1   │         │ 1┤      ___vout                     │
│             │   ■ vout     │.785/.894│  ┤  ___/  ‾‾‾‾vref (наложение)     │
│             │   ■ vref     │.800/.800│ 0┤_/                                │
│             │   Y 0…1 🔒 ⇕ │         │                                     │
└─────────────┴──────────────┴─────────┴─────────────────────────────────────┘
```

- Слева — док с деревом иерархии (все открытые дампы) и фильтром над ним.
- Справа — список строк: колонка имён, колонка значений под курсорами
  (`@A / @B`), холст волн с линейкой времени сверху.
- Колонки имён/значений и дерево меняют ширину; раскладка доков сохраняется
  в `QSettings`.

### 4.3. Строки

Строка — элемент вертикального списка вида. Строки переставляются
перетаскиванием, удаляются, копируются. Виды строк:

**Цифровая строка** — один сигнал wasafe (лист или композит), либо его битовый
срез.

- Бит — ступенька; шина — «шестигранники» со значением внутри, текст
  обрезается, если не влезает.
- `x` и `z` отображаются отлично от 0/1 (общепринятая конвенция: `x` — красным,
  `z` — средним уровнем); конкретные цвета — разработчику.
- Если на пиксель приходится больше одного изменения — «плотная» заливка
  вместо мешанины линий.
- Формат отображения на строку: bin, oct, hex, unsigned dec, signed dec, ASCII;
  для `ENUM` — имена; для `STRING` — строка; для `EVENT` — отметки.
- VCD перечислений не несёт: enum из Icarus приходит обычным вектором и
  показывается числом. Имена (`IDLE/RUN` на макете) в v1 доступны только
  у строковых переменных (`$var string`, значения `s…`) — они рисуются
  текстом в «шестигранниках» и ищутся по строке. Пользовательские таблицы
  «значение → имя» (как translate-файлы GTKWave) — не в v1, появятся вместе
  с форматами, где enum есть.
- Реверс битов — модификатор строки.
- Композиты wasafe (struct/array) раскрываются в дочерние строки.
- **[решение спеки]** Вектор можно поместить в аналоговую панель — тогда он
  рисуется как число (unsigned/signed по формату). Полезно для кодов АЦП/ЦАП
  поведенческих моделей.

**Папка-группа** — сворачиваемый контейнер для любых строк (включая аналоговые
панели и другие папки); только организация, значения не имеет.

**Составной сигнал** — виртуальная packed-структура, задаваемая пользователем:
упорядоченный список полей, каждое поле — сигнал или его битовый срез (из
любого открытого дампа), у поля есть имя (по умолчанию — имя сигнала).

- В свёрнутом виде — одна шина, склейка битов всех полей (первое поле —
  старшие биты); формат и реверс применяются к склейке.
- В развёрнутом — поля по именам, каждое со своим форматом.
- Создание: выделить строки → «Объединить»; редактирование состава и порядка
  полей; переименование.
- Внутреннее представление (вычисляется ли в ядре Phosphor слиянием курсоров
  или станет вычисляемым потоком wasafe) — разработчику, с учётом того, что
  математика позже, вероятно, переедет в wasafe (раздел 8).

**Аналоговая панель** — строка, внутри которой один или несколько наложенных
сигналов с общей осью Y (раздел 4.4).

### 4.4. Аналог

Аналоговый сигнал — `REAL` (или вектор, помещённый в панель, см. 4.3).

- **Панель** содержит 1..N следов, у каждого свой цвет, легенда в колонке имён.
  След переносится между панелями перетаскиванием; сигнал можно добавить в
  существующую панель или создать новую.
- **Высота** панели тянется мышью за нижнюю границу.
- **Ось Y** с подписями делений внутри панели и горизонтальной сеткой.
  **[решение спеки]** Одна ось Y на панель; сигналы разных порядков величины
  кладутся в разные панели. Вторая ось в панели — не в v1.
- **Масштаб Y** — режимы:
  - авто по видимому окну;
  - авто по всему дампу (диапазон фиксирован, не меняется при прокрутке);
  - ручной: «замок» фиксирует текущий диапазон; диапазон вводится числами
    в свойствах панели, меняется жестами (колесо с модификатором, рамка
    выделения по Y — конкретные жесты на усмотрение разработчика).
- **Отрисовка между точками** — режим каждого следа: ступенька (по умолчанию —
  так честнее для `real` поведенческих моделей) или линейная интерполяция.
- **Отдаление.** Когда на пиксель приходится много точек, рисуется огибающая
  min/max по пиксельным колонкам, без потери пиков.
- **Значения на пересечениях:** на пересечении каждого курсора с каждым следом —
  маркер-точка и подпись со значением (в режиме интерполяции — интерполированное
  значение). Значения форматируются в инженерной нотации (`785m`, `1.2µ`).
- Единиц измерения в VCD нет. **[решение спеки]** Пользователь может задать
  панели подпись единиц (строка, только для отображения).

### 4.5. Время, масштаб, курсоры

- Масштаб по времени: колесо с модификатором вокруг указателя, кнопки −/+,
  «вписать всё», «вписать между курсорами», рамка выделения на линейке.
- Прокрутка по времени: горизонтальная полоса, колесо/тачпад.
- Вертикальная прокрутка списка строк; колонки имён/значений прокручиваются
  синхронно с холстом.
- **Курсоры A и B**: ставятся кликом (A — левой, B — с модификатором или
  средней кнопкой — на усмотрение разработчика), перетаскиваются, показываются
  на линейке; между ними Δt. Колонка значений показывает значения каждой строки
  под A и под B.
- Горячие клавиши для всего перечисленного; раскладка клавиш — разработчику,
  желательно близко к SimVision (цифра, навигация, курсоры) и Virtuoso/ViVA
  (аналоговые панели), см. ориентир в разделе 1.

### 4.6. Поиск

1. **Сигнал в иерархии.** Поле фильтра над деревом. Режимы: подстрока (по
   умолчанию), glob (`*fifo*.wr_*`), regex. Сопоставление — по полному пути.
   **Результат остаётся деревом**: неподходящие узлы скрываются, предки
   найденных остаются и раскрываются. Индекс имён для фильтра строит само
   приложение (в wasafe `Database::find` ищет только по точному пути). Из
   дерева сигнал добавляется в вид: Enter, двойной клик, перетаскивание.
2. **Значение выбранного сигнала по всей диаграмме.**
   - Значение вводится в формате строки (`3C` в hex, `60` в dec, имя для enum).
     **[решение спеки]** Для шин — маска в стиле `casez`: `?` — «любое значение
     бита», а `x` и `z` — буквально «бит равен X / Z»
     (`8'b1?0?_????`, `8'bxxxx_xxxx`). Так ищется и «шина стала X».
   - Для аналога — пересечение уровня (вверх / вниз / любое) и условия `>`, `<`.
   - Режимы: «следующее / предыдущее вхождение» (переносит курсор A и
     прокручивает вид) и «найти все» (список времён, переход по клику).
   - Работает в фоне, с прогрессом и отменой.
3. **Фронты.** Следующее/предыдущее изменение выбранного сигнала; для
   однобитного — отдельно передний и задний фронт. Двигают курсор A. Если
   выделено несколько строк — ближайшее изменение среди них.

### 4.7. Сессия и настройки

- **Файл сессии** — «что я смотрю»: список открытых дампов (пути относительно
  файла сессии), все строки с их видом (порядок, папки, составные сигналы,
  форматы, реверс, панели, их высоты, режимы и диапазоны Y, интерполяция,
  цвета, подписи), курсоры, видимое окно времени. Формат — JSON
  (`QJsonDocument`) с полем версии формата. Сигналы — по полному пути (не по
  `NodeId`: id меняются при переиндексации). Время — в абсолютных единицах, не
  зависящих от timescale конкретного дампа.
- «Перечитать» использует то же состояние, что и сессия (сериализация вида
  в память → переиндексация → применение).
- **`QSettings`** — настройки приложения: геометрия окна и раскладка доков,
  недавние файлы и сессии, цвета, умолчания.
- **[решение спеки]** Undo/redo для правок вида (добавить/удалить/переместить
  строки, сменить формат, изменить панель и т. п.) — в v1, раз все изменения
  состояния и так идут через команды (раздел 6).

### 4.8. Командная строка

`phosphor [dump.vcd ...] [-s session.json]` — открыть дампы и/или сессию.

## 5. Нефункциональные требования

### 5.1. Производительность

Ориентир — дамп 600 МиБ VCD, десятки тысяч сигналов, десятки видимых строк.

| Действие | Цель |
| --- | --- |
| Запуск до окна | < 1 с |
| Повторное открытие дампа (свежий `.wsfstore` в кэше) | < 1 с до первой отрисовки |
| Первое открытие 600 МиБ VCD | ограничено wasafe (~8 с по их замерам); прогресс + отмена; GUI не блокируется |
| Прокрутка/масштаб по времени при подгруженных данных | плавно, кадр ≤ 16 мс |
| Отрисовка после прыжка в новую область или сильного отдаления | ≤ 100 мс; если не успели — сначала грубая картинка, затем уточнение; замороженного GUI не бывает |
| Фильтр дерева | ≤ 50 мс на нажатие клавиши |
| Поиск значения/фронта | рядом — мгновенно; по всему дампу — секунды, в фоне, с прогрессом и отменой |
| «Перечитать» | время переиндексации; вид восстанавливается сразу после неё |

**[решение спеки]** Условия проверки:

- эталон — рабочая машина заказчика (Linux, NVMe); на Windows — тот же стенд
  как проверка отсутствия регрессий, без жёстких порогов;
- холст шириной 1920 px (FullHD), 50 видимых строк, из них 4 аналоговые
  панели по 2–3 следа;
- «повторное открытие» и «прыжок» — на тёплом файловом кэше ОС; холодный кэш
  замеряется и фиксируется в отчёте стенда, но порогом не является;
- построение сводок (раздел 7) удлиняет первую индексацию не более чем
  на 20 % относительно wasafe без сводок.

Следствия:

- ни одного обращения к БД wasafe в GUI-потоке;
- пирамида сводок в wasafe (раздел 7);
- **стенд**: генератор синтетического большого VCD (порядка 600 МиБ, ≥ 10 000
  сигналов, в т. ч. `real` и плотные шины) и безголовый замер ключевых операций
  ядра (открытие, подготовка кадра при разных масштабах, поиск). Цели таблицы
  проверяются стендом, а не декларируются.

### 5.2. Платформы и сборка

- Linux и Windows, C++23 (GCC 14+, Clang 18+, MSVC 19.40+ — как у wasafe).
- Qt 6 подключается через `find_package(Qt6)` от любой установки (системный
  Qt 6.12 на Arch; установщик Qt или vcpkg на Windows), **не** через Conan:
  рецепт Qt в Conan собирается часами. Остальные зависимости — Conan, как сейчас.
- Тесты — GoogleTest (ядро). Тесты виджетов — по необходимости.
- Стиль кода — как в wasafe (исключения как модель ошибок, комментарии на
  русском, `.clang-format`/`.clang-tidy` проекта, структура классов по
  глобальным правилам заказчика).

### 5.3. Надёжность

- Битый или неполный VCD — сообщение об ошибке, не падение.
- Отмена любой долгой операции оставляет приложение в согласованном состоянии.

## 6. Архитектура (согласовано)

**UI — Qt Widgets, без QML.** Доки, деревья, таблицы, меню и диалоги — сильная
сторона Widgets; docking'а в QML нет. Холст волн — собственный `QWidget`,
рисующий `QPainter`'ом уже прорежённые примитивы (на колонку пикселей —
отрезок min/max или метка перехода, а не каждое изменение). Переход на GPU
(QRhi) возможен позже за тем же интерфейсом.

**Слои** (зависимости только сверху вниз):

```plaintext
 UI (Qt Widgets)       окно, доки, дерево, список строк, холст, диалоги
        │  команды ▼   ▲ события «состояние изменилось», готовые кадры
 Ядро (без QtGui/Widgets; QtCore допустим)
   Session   — открытые источники (дампы), общая ось времени
   View      — строки, папки, составные сигналы, панели, курсоры, окно времени
   Commands  — все изменения состояния; undo/redo; сериализуемые
   Render    — прореживание: (строка, окно времени, ширина в пикселях) → примитивы
   Search    — поиск значений/фронтов, индекс имён
        │
 wasafe / wasafe-vcd   Database, LazyStorage, VcdReader
```

- **Ядро не знает о виджетах.** Позже к нему же подключатся MCP-сервер, второе
  окно и математика. Поэтому все изменения состояния — только через команды.
- **Session и View разделены**: источники данных общие, вид — отдельный
  объект. В v1 одно окно и один вид, но второе окно потом — второй View над
  той же Session.
- **Потоки.** `Database` wasafe не потокобезопасна; второму потоку нужен свой
  `db.duplicate()` (свой LRU и дескриптор файла). Рабочие потоки (отрисовка,
  поиск) держат свои дубликаты и отдают наверх готовые результаты — примитивы
  кадра, найденные времена, — а не хэндлы и не `ValueView`. Между потоками
  передаются только `NodeId`/пути и значения-копии. Устаревшие задачи
  (пользователь уже прокрутил дальше) отменяются.
- **Подготовка кадра** кэшируется (например, тайлами по времени на уровень
  масштаба), чтобы прокрутка при подгруженных данных не требовала обращений
  к БД. Стратегия кэша — разработчику, критерий — таблица 5.1.

## 7. Доработки соседних библиотек (в объёме v1)

Заказчик разрешил менять wasafe и wasafe-vcd, если не хватает функциональности
или решения неудачны. Для v1 нужно:

1. **wasafe: сводки для отдаления.** Сейчас у блока (`BlockRef`) есть только
   диапазон времени, размеры, CRC и число изменений; сводки значений нет, и при
   сильном отдалении пришлось бы распаковывать все блоки окна. Нужно: для `REAL`
   — min/max по блоку и многоуровневая пирамида поверх блоков; для logic —
   достаточно данных, чтобы рисовать «плотные» участки и наличие `x`/`z` без
   распаковки. Сводки строятся индексирующим builder'ом за тот же проход и
   хранятся в метаданных `.wsfstore` (с повышением minor-версии секции).
   Конкретный формат — разработчику; критерий приёмки — таблица 5.1 на стенде.
2. **wasafe-vcd (и/или wasafe): прогресс и отмена разбора.** Сейчас у
   `Reader`/`ingest` нет ни того, ни другого. Отмену можно сделать и без правок
   библиотек — декоратором `Builder`, бросающим исключение по флагу; прогресс
   требует от `VcdReader` сообщать позицию в файле (колбэк или опрашиваемый
   счётчик). Способ — разработчику.

## 8. Заделы под следующие этапы

Ничего из этого в v1 не делается, но архитектура не должна мешать:

- **Live-просмотр** недописанного VCD (кнопка, таймер, `QFileSystemWatcher`,
  «следовать за концом»). Потребует возобновляемого чтения в wasafe-vcd и
  растущей БД в wasafe. Требование к v1: ядро не считает диапазон времени и
  данные неизменными — источник может сообщить «данные выросли до T», и
  прореживание, кэши кадров, поиск и курсоры это переживают (кэши
  инвалидируются по событию, а не держат «конец диаграммы» как константу).
- **Математика над сигналами** — вероятно, вычисляемыми потоками в самом
  wasafe. Составной сигнал v1 — первый «вычисляемый» сигнал; его стоит устроить
  так, чтобы он естественно лёг в ту же модель.
- **Сравнение баз** — поверх математики (`diff(a, b)`), с сопоставлением путей
  и допусками. Модель нескольких источников v1 — его основа.
- **Несколько окон** — несколько View над одной Session.
- **MCP** — поверх команд и запросов ядра.
- **Экспорт / редактирование** — через `Writer` wasafe (`VcdWriter` уже есть).
- **Настройка хранения** — выбор режима (ОЗУ / store) и места store
  (раздел 4.1).
