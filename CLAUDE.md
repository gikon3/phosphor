# Phosphor

Просмотрщик временных диаграмм на Qt6 (Widgets) поверх wasafe / wasafe-vcd.
Ориентир по удобству — SimVision (цифра) + Virtuoso/ViVA (аналог).

- Спека v1: [docs/superpowers/specs/2026-10-24-phosphor-design.md](docs/superpowers/specs/2026-10-24-phosphor-design.md)
- Этапы 0–1 (скелет и вертикальный срез) завершены:
  [docs/superpowers/plans/2026-10-24-phosphor-stage0-1.md](docs/superpowers/plans/2026-10-24-phosphor-stage0-1.md).
  Перечень следующих этапов — в его конце («Что сознательно не входит»).
- Следующий этап планируется от спеки и [docs/backlog.md](docs/backlog.md): раздел
  «Высокий приоритет» — то, с чего начинать. Исходные замеры — README, раздел «Стенд».

## Сборка и тесты

```bash
.venv/bin/conan install . --build=missing -s compiler.cppstd=23 -s build_type=Debug
cmake --preset conan-debug
cmake --build --preset conan-debug
ctest --preset conan-debug --output-on-failure
```

- Qt 6 — системный, через `find_package(Qt6)`; через Conan его не тянуть.
- [wasafe](https://github.com/gikon3/wasafe) и
  [wasafe-vcd](https://github.com/gikon3/wasafe-vcd) приходят через Conan; при
  совместной разработке их удобно подключать как editable-пакеты. Их можно
  дорабатывать, если не хватает функциональности, но это отдельные репозитории
  со своими правилами.
- Найденный в них дефект или нужная доработка записывается в `docs/backlog.md`
  того репозитория (что наблюдается, воспроизведение, что ожидается, откуда
  пришло), чтобы агент в том репозитории мог взять пункт в работу. Коммитит там
  пользователь.
- Два тестовых бинарника: `phosphor-core-tests` (только `phosphor::core`, на
  `QCoreApplication` — так сборка проверяет, что ядро не зависит от виджетов) и
  `phosphor-ui-tests` (`QApplication`, `QT_QPA_PLATFORM=offscreen` по умолчанию).
  Файлы тестов перечисляются в `tests/CMakeLists.txt` явно, без `file(GLOB)`.
- Санитайзеры и Release — пресеты `conan-debug-tsan`, `conan-debug-asan-ubsan`,
  `conan-release` (профили Conan `clang-tsan`, `clang-asan-ubsan`, сборка `Release`). При
  editable-зависимостях wasafe и wasafe-vcd должны быть собраны тем же профилем в своих
  репозиториях, иначе пакеты указывают на несуществующий каталог сборки:

  ```bash
  .venv/bin/conan install . -pr clang-tsan -s compiler.cppstd=23 --build=missing
  cmake --preset conan-debug-tsan
  cmake --build --preset conan-debug-tsan
  ctest --preset conan-debug-tsan
  ```

- Формат и статический анализ — скрипты `.claude/scripts/clang-format.sh [--check] [файлы]`
  и `.claude/scripts/clang-tidy.sh -p build/Debug [файлы]` (без файлов — всё изменённое
  относительно HEAD; `.hpp` проверяется через включающие его `.cpp`). Хук Claude Code сам
  форматирует правленые `.cpp/.h/.hpp`.
- Стенд производительности — README, раздел «Стенд» (`tools/gen_vcd.py`, `phosphor-bench`,
  опция `PHOSPHOR_BUILD_BENCH`).

## Устройство

- `src/core/` → `phosphor_core` (`phosphor::core`): без QtGui/Widgets, QtCore
  допустим. Сессия, вид, команды, прореживание, рабочие потоки. Всё, что позже
  понадобится MCP и второму окну, живёт здесь.
- `src/app/` → `phosphor_ui` (`phosphor::ui`): виджеты. `src/main.cpp` → `phosphor`.
- Имена целей CMake — через подчёркивание (`phosphor_tests`), alias —
  `phosphor::<кратко>`, имя файла (`OUTPUT_NAME`) — через дефис (`phosphor-tests`).
- Время в ядре — `GlobalTime`, int64 в фемтосекундах; у каждого дампа свой
  `TimeAxis`.
- Сигналы в виде и сессии ссылаются на пару «источник + полный путь», не на
  `NodeId`: id меняются при переиндексации.

### Как устроено сейчас (неочевидное — не «упрощать» обратно)

- **Session** грузит каждый дамп в своём `std::jthread` (`loadDump` → `.wsfstore` в кэше) и
  отдаёт результат в свой поток через очередь Qt. У источника две БД: для иерархии в GUI-потоке
  и копия `duplicate()` для рендерера. `sourceAboutToBeRemoved` приходит, пока данные живы, и
  обрабатывается только прямым соединением: на нём модель дерева удаляет строки.
- **Renderer** — один рабочий поток со всеми БД значений. Побеждает последний запрос, кадры
  приходят по возрастанию поколения. Готовый кадр лежит в ящике на одно место под мьютексом, а
  в GUI уходит пустое собственное событие Qt: лямбда или указатель на метод через очередь дают
  ложные срабатывания TSan с несобранной под TSan системной Qt.
- **Прореживание** (`buildDigitalFrame`) переводит изменения в спаны по пикселям тем же
  отображением время→пиксель, что и курсоры; плотный пиксель (≥ 2 изменения) пропускается
  перескоком к следующему, поэтому цена кадра — по пикселям, а не по изменениям.
- **WavePanel** — единственное место, где меняется окно времени из UI (`applyWindow`: не
  левее начала данных); запросы кадров схлопываются до одного за итерацию цикла событий;
  кадр сопоставляется строкам по сигналу и формату, а не по индексу.
- **Кэш store**: имя `<stem>-<хеш пути>-<хеш размера и mtime>.wsfstore`; после публикации
  старые версии того же дампа удаляются. Каталог — `GenericCacheLocation/<kName>/stores`.

## Инварианты

- В GUI-потоке у `WaSafe::Database` можно только ходить по иерархии. Никаких
  `valueAt` / `changes` / `nextChange` / `prevChange`: значения читают рабочие
  потоки через собственный `duplicate()`.
- `WaSafe::Signal`, `Scope`, `ValueView` не пересекают границу потока; передаются
  `NodeId`, пути и значения-копии.
- Медленная работа — главный критерий провала (спека, раздел 5.1). Изменения,
  затрагивающие загрузку и отрисовку, проверяются стендом `bench/`.

## Код

- C++23, пространство имён `Phosphor`, файлы `snake_case`, методы `camelCase`,
  закрытые поля с суффиксом `_`. Ошибки — исключениями (`Phosphor::Error`).
- Форматирование — `.clang-format`, проверки — `.clang-tidy`; оба прогоняются
  по изменённым файлам перед тем, как показывать результат
  (`clang-tidy -p build/Debug <файлы .cpp>`).
- Однострочное тело `if`/`else`/`while`/`for` — без фигурных скобок; в цепочке
  `if / else if / else` скобки либо у всех веток, либо ни у одной.
- Вызов конструктора класса — фигурными скобками вместо круглых, где это
  возможно (`QApplication app{argc, argv}`, `: db_{db}` в списке инициализации).
  Скаляры, константы и `auto` инициализируются присваиванием
  (`constexpr int kMinExponent = -15;`, `const auto x = f();`).
- Без лишних скобок вокруг арифметики с обычным приоритетом: `a + b * c`, а не
  `a + (b * c)`; скобки — только там, где они меняют смысл или смешаны сдвиги и
  побитовые операции.
- Вместо «bool + out-параметр» — `std::optional<T>`.
- Параметр, который только читает непрерывную последовательность, — `std::span<const T>`,
  а не `const std::vector<T>&`; так же отдаётся наружу внутренний вектор только для чтения
  (с оговоркой о времени жизни в комментарии).
- Виджет получает родителя при создании (`new QTreeView{dock}`), а не позже, при передаче в
  раскладку или док: исключение между созданием и передачей иначе оставило бы его без владельца.
- Qt собирается с `QT_NO_KEYWORDS` (у wasafe есть члены с именем `signals`):
  писать `Q_SIGNALS` / `Q_SLOTS` / `Q_EMIT`, а не `signals` / `slots` / `emit`.
- Строковые литералы в коде — на английском, без кириллицы (сообщения
  исключений, логи, CLI). Видимый пользователю текст GUI — через `tr()` с
  английским исходником; русский живёт только в файлах переводов.
- Структура класса: блоки по видимости `public` → `protected` → `private`; внутри
  видимости — типы, константы, методы (фабрики, специальные члены, обычные,
  операторы), поля. Спецификатор доступа пишется перед каждым блоком, пустые
  блоки не пишутся, агрегаты — без спецификаторов. Определения в `.cpp` идут в
  порядке объявления.
- Комментарии на русском. Комментарий описывает текущий контракт и причину; он
  не ссылается на прошлую реализацию, на код в других файлах и не называет
  вызывающих (кроме типа, который существует ради конкретного потребителя).

## Работа по плану и коммиты

- После каждой задачи плана остановиться: прогнать сборку и тесты, честно
  привести результат, кратко показать сделанное и предложить сообщение коммита.
  Коммитить только после того, как пользователь скажет продолжать.
- Агенты-исполнители задач не коммитят; коммит делает основной сеанс.
- Ветки: `feat/…`, `fix/…`. В `main` напрямую не коммитить.
- Сообщение коммита: префикс, двоеточие, коротко по-русски без точки в конце.
  Префиксы: `add:` (новое), `fix:` (исправление), `mod:` (изменение поведения),
  `refactor:` (без изменения поведения), `build:` (сборка, зависимости, CI),
  `doc:` (документация). Тело — только если нужно объяснить «почему».
